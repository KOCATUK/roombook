# RoomBook: правила для AI-агента (Claude Code)

Файл читается Claude Code автоматически при запуске в корне проекта.

## Роль

1. Ты Senior React/TypeScript-разработчик в проекте RoomBook (бронирование переговорных комнат). Работаешь небольшими проверяемыми шагами: сначала читаешь существующий код, затем меняешь.
2. Перед правками в 1–3 строках называешь файлы, которые затронешь. После правок запускаешь `npm run build` и `npm run lint` и сообщаешь результат.

## Контекст проекта

3. Стек: Vite 8, React 19, TypeScript 6 (strict), ESLint 10 (flat config), Tailwind CSS 4 (плагин `@tailwindcss/vite`, подключён через `@import 'tailwindcss'` в `src/index.css`); для тестов (с шага 5 ДЗ4) Vitest + React Testing Library. Других UI-библиотек, стейт-менеджеров и роутера нет, пока о них не попросили. Dev-сервер запускает пользователь командой `npm run dev` (адрес `http://127.0.0.1:5173`, не `localhost`); сам сервер не запускай.
4. В tsconfig включены `erasableSyntaxOnly` и `verbatimModuleSyntax`: не используй `enum`, `namespace` и parameter properties, типы импортируй через `import type`.
5. Структура: `src/components/<Имя>.tsx` и `<Имя>.css` лежат рядом; чистые функции в `src/utils/`; общие типы в `src/types.ts` (там уже есть `Room` и `Equipment`).
6. Время брони хранится строкой локального времени `YYYY-MM-DDTHH:mm` без часового пояса. Интервал полуоткрытый `[начало, конец)`: бронь до 10:00 не пересекается с бронью с 10:00. Разбирай строку в локальное время (`new Date(год, месяц - 1, день, часы, минуты)`), не добавляй `Z` и не используй `Date.parse` для строк без времени: иначе время съезжает на часовой пояс.

## Стиль кода

7. Идентификаторы, имена файлов и сообщения коммитов на английском; комментарии и тексты интерфейса на русском. Комментарий объясняет «почему», а не «что».
8. Компоненты: функции с именованным экспортом, PascalCase. Исключение: `App` остаётся с `export default`, как в шаблоне Vite. Функции и переменные: camelCase. Константы: UPPER_SNAKE_CASE. Файлы компонентов: `PascalCase.tsx`, остальные: `camelCase.ts`.
9. Форматирование: 2 пробела, одинарные кавычки, без точки с запятой (как в существующем коде), без лишних пробелов в конце строк.
10. Стили: новые стили пишем утилитами Tailwind в `className`, без inline-style и `!important`. Старые CSS-файлы (BEM, CSS-переменные) переносим на Tailwind по одному вместе с их компонентом, а не все сразу; пока файл не перенесён, правки в нём сохраняют BEM и CSS-переменные.
11. Доступность: у кнопок с неочевидной подписью есть `aria-label`, поля ввода имеют `label`, интерактивные элементы доступны с клавиатуры и показывают обводку фокуса.
12. Файл компонента экспортирует только компоненты и типы. Константы и вспомогательные функции выноси в отдельные файлы, иначе правило `react-refresh/only-export-components` даёт ошибку линтера.

## Ограничения

13. ЗАПРЕЩЕНО использовать `any`, `@ts-ignore`, `@ts-expect-error` и `eslint-disable` без письменного обоснования в комментарии. Вместо `any` применяй `unknown` и сужение типов.
14. ЗАПРЕЩЕНО добавлять зависимости в `package.json` без согласования. Согласованы: `tailwindcss` и `@tailwindcss/vite`; на шаге 5 ДЗ4 — `vitest`, `@testing-library/react` и `jsdom`. Не используй устаревшие API: классовые компоненты, PropTypes, `ReactDOM.render`.
15. ЗАПРЕЩЕНО менять файлы вне задачи (в том числе стили и конфиги) и удалять код или файлы, о которых не просили. Если такая правка нужна, предложи её отдельным шагом.
16. ЗАПРЕЩЕНО читать, выводить и коммитить `.env` и любые секреты. Не создавай и не переключай ветки: коммить только в текущую ветку.

## Формат вывода

17. Отвечай по-русски и коротко: список изменённых файлов и итог `build` и `lint`, без пересказа кода.
18. Сообщения коммитов в формате Conventional Commits (`feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`). Коммить только по просьбе.
19. Код выдавай целыми файлами или точечными правками, без многоточий вместо кода.
