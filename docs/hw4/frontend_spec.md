## Технологический стек

| Что | Выбор | Зачем |
|---|---|---|
| Фреймворк | React 19 + TypeScript 6 (strict) | уже используется в прототипе ДЗ1–ДЗ3 |
| Сборка | Vite 8 | уже настроена, hot reload через `npm run dev` |
| UI-библиотека | Tailwind CSS 4 (плагин `@tailwindcss/vite`) | быстрая адаптивная вёрстка через утилиты и брейкпоинты |
| Тесты | Vitest + React Testing Library + jsdom | поддерживают Vite из коробки |
| Данные | Mock API в `src/api/` с задержкой и имитацией сбоев | сервер появится в ДЗ5 |
| Агент | Claude Code с правилами из `CLAUDE.md` | как в ДЗ2 |

Роутер и стейт-менеджер не нужны: приложение — один экран.

## Функции, реализуемые в ДЗ4 (из ТЗ ДЗ3)

### Функция 1. Каталог комнат и статус
- Требования: FR-01…FR-06 (карточки, статус «Свободна» или «Занята до HH:mm · название», сводка, пустой список).
- Состояния: загрузка (скелетон карточек), ошибка загрузки с кнопкой «Повторить» (FR-42), пусто «Комнат пока нет» (FR-06), успех.

### Функция 2. Бронирование с проверкой пересечений
- Требования: FR-07…FR-18 (форма, валидация, сообщения об ошибках, уведомление об успехе).
- Состояния: отправка (кнопка заблокирована, подпись «Сохранение…»), ошибка сохранения с баннером «Не удалось сохранить бронь» и кнопкой «Повторить», введённые данные не теряются (FR-40), успех с уведомлением (FR-09), конфликт «Это время только что заняли. Выберите другое время» (FR-44).

### Функция 3. Расписание комнаты и отмена брони
- Требования: FR-21…FR-23 (список по времени, пустое расписание, отмена с подтверждением).
- Состояния: загрузка расписания, ошибка загрузки, пусто «Броней пока нет», отмена в процессе, ошибка отмены.
- Не входит в ДЗ4: FR-24 (отмена только своей брони) и вход в аккаунт, они требуют сервера и авторизации (ДЗ5).

## Mock API

Функции `getRooms`, `getBookings`, `createBooking`, `cancelBooking` возвращают `Promise` с задержкой 400–800 мс. Сценарий выбирается параметром адреса: `?scenario=ok` (по умолчанию), `?scenario=slow`, `?scenario=error` (ошибка загрузки), `?scenario=saveError` (ошибка сохранения), `?scenario=empty` (нет комнат). Так все состояния можно показать вручную и проверить в тестах.

## Нефункциональные требования ДЗ4

- Адаптивность: ширины 360, 390, 768 и 1280 px без горизонтальной прокрутки (FR-37, FR-38).
- Доступность: у состояний загрузки и ошибок есть `role="status"` или `role="alert"`, поля с `label`, фокус виден.
- Тесты: не менее трёх автоматических (позитивные и на ошибки), команда `npm test` проходит.
- Качество: `npm run build` и `npm run lint` без ошибок.
